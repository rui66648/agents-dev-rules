# 项目现状（实时上下文）

> **项目现状**是 AI 代理开始工作前必须获取的实时项目快照，用于替代"读取历史文档"的假设。

## 什么是项目现状

| 维度 | 内容 | 获取方式 |
|------|------|----------|
| **代码状态** | 当前分支、未提交变更、最近提交 | `git status` + `git log --oneline -5` |
| **运行状态** | 哪些服务在运行、占用了哪些端口 | `netstat` / `docker ps` |
| **文档状态** | 已存在哪些设计文档、是否已审批 | 扫描 `docs/designs/*.md` |
| **依赖状态** | 关键依赖版本、是否有安全漏洞 | `package.json` / `pyproject.toml` |
| **已知问题** | 当前阻塞项、待修复 Bug、技术债务 | 用户口述 + 代码注释 |

## 何时获取项目现状

**必须获取**（阻塞）：
- 用户首次提出需求时（任何**代码相关**请求；纯问答/解释类请求可跳过，避免对简单任务强制扫描）
- 设计文档批准后、进入 writing-plans 前
- 执行计划前（确认当前代码基线）

**建议获取**（非阻塞）：
- 每次对话开始时（快速确认上下文未过期）
- 用户提到"之前做的"、"上次说的"时

## 获取流程

```
用户提出需求
    │
    ▼
[快速扫描] 检查当前目录文件列表
    │
    ▼
[分支判断]
    ├─ 有未提交变更 → 询问用户是否先提交
    ├─ 有进行中的设计文档 → 读取并确认状态
    ├─ 有运行中的服务 → 记录端口占用情况
    └─ 全新上下文 → 声明"绿场/空项目"
    │
    ▼
[输出现状摘要] 1-3 句话描述当前状态
    │
    ▼
基于现状给出方案
```

## 现状摘要模板

```
[项目现状]
- 分支: main (2 个未提交文件)
- 运行中: 后端 API @ :8000 (Python), 前端 Dev @ :5173
- 设计文档: docs/designs/2026-07-24-auth-design.md (已审批)
- 阻塞项: 无
- 建议: 基于已审批的认证设计继续实现
```

## 硬性规则（v1.2.0，ADR-006）

- ✅ **涉及代码改动的方案**，输出前先核对项目现状（分支/未提交变更/相关文档/运行状态）
- ✅ **发现上下文与用户描述冲突时必须指出**
- ❌ **禁止假设项目状态**
- ❌ **禁止忽略未提交变更**

> **已删除**："任何方案输出前必须获取现状""现状摘要必须包含在响应开头"。前者对纯问答/解释类请求是冗余开销，后者把手段变成了格式表演；现状摘要在**确实相关时**给出即可。

## 功能完成度定义

> 任务完成度是衡量实现质量的量化标准。"完成"声明必须基于客观的完成度等级，而非主观判断。

| 等级 | 定义 | 判定标准 |
|------|------|----------|
| 🟢 完整 | 全部功能实现 + 全部 API 对接 | 设计文档中的功能点 100% 实现，API 集成矩阵全部标记"已对接" |
| 🟡 部分 | 核心功能实现，部分非核心功能/API 未对接 | 至少 80% 功能点可用，核心流程无阻塞 |
| 🔴 骨架 | 组件存在，核心功能未实现或 API 未对接 | 仅 UI 渲染，无数据交互，或关键 API 未对接 |

**进度标记规则：**
- 任务项标记 "✅" 仅当完成度达到 **🟢 完整**
- 未达到完整等级的任务标记 "⏳" 并注明当前完成度等级（如 ⏳ [🟡 部分]）
- 设计文档批准后，AI 自动估算每个任务的初始完成度

**禁止行为：**
- ❌ 禁止将"组件存在但未对接 API"标记为 ✅
- ❌ 禁止在完成度未达 🟢 完整时声明"任务完成"
- ❌ 禁止跳过 API 集成矩阵的"对接状态"更新
