# Agent 上下文管理指南 (Agent Context Management)

> **v2.0.0 精简说明（ADR-006）**：删除代码知识图谱、Redis 缓存、自建快照与"规则库 ≤15%"等硬性百分比预算。这些要么由运行时原生能力（会话、轨迹、子代理、检索工具）承担，要么无法度量。保留"按需加载"这一真正有用的原则。

## 1. 核心原则：按需加载

- 规则、代码与文档**按任务需要读取**，不预载无关内容。
- 加载顺序：先 `tech-stack.md` 与任务直接相关的少量文件，遇到专项（安全、DB、测试）再补读对应规则。
- **不设硬性百分比预算**：上下文是否够用由任务复杂度决定；当明显冗余时，主动精简已不再相关的读取结果。
- 已读规则若与当前任务无关，不要求长期驻留或机械"清理"。

> 入口路由见 `AGENTS.md` §2：每类任务读"必须读取"列，按需再读"可选读取"列。

## 2. 运行时优先（不重复造轮子）

以下能力**优先使用运行时/现成工具**，禁止自建等价实现（RULE-017 / RULE-051）：

| 能力 | 用运行时/现成工具 | 不再自建 |
|------|------------------|----------|
| 代码检索 | grep / glob / 语义搜索 | 代码知识图谱 |
| 依赖分析 | `pipdeptree`、`npm ls` 等生态工具 | 自研依赖图 |
| 会话持久化 / 恢复 | 运行时 session（resume / fork / search） | 自建快照 + Redis |
| 操作轨迹 / 审计 | 运行时 trajectory 日志 | 自建审计 JSONL |
| 任务隔离 | 运行时 subagent / 独立 session | 自建上下文隔离器 |
| 缓存 | 现成缓存插件（需要时） | 自研缓存框架 |

## 3. 记忆资产分层（按需沉淀）

> 缓存是可丢弃的临时数据；记忆资产是有版本、可复用的内容。区分二者，避免把临时数据当资产长期保留。

| 资产类型 | 内容 | 生命周期 | 版本管理 |
|---------|------|---------|---------|
| 会话记忆 | 对话历史、用户偏好 | 会话级 | 无 |
| 技能资产 | 可复用技能/工作流（`skills/`） | 项目级 | Git |
| 决策与知识 | ADR、设计文档、研究（`docs/`） | 项目级 | Git |

**原则**：有复用价值才沉淀（RULE-015 YAGNI）；临时缓存不做长期资产。

## 4. 检查清单

- [ ] 是否只读了与任务相关的规则与代码？
- [ ] 是否优先使用了运行时检索/会话/子代理能力，而非自建？
- [ ] 沉淀到 `docs/` 或 `skills/` 的内容是否有复用价值？

## 5. 禁止事项

- ❌ 自研知识图谱 / 缓存框架 / 快照管理器（优先运行时或现成方案）
- ❌ 把临时缓存当资产长期驻留
- ❌ 为凑"预算比例"而机械清理仍有用的上下文
