# 优先级体系

| 优先级 | 来源 | 说明 |
|--------|------|------|
| **最高** | 用户直接指令 | 用户在对话中明确要求的 |
| **高** | `tech-stack.md` | 项目特定技术约束 |
| **高** | AGENTS.md + `rules/` | 通用铁律，不可违反 |
| **中** | `skills/` 技能定义 | 工作流行为指导 |
| **低** | `agents/` 代理建议 | 专业角色建议，可协商 |

**冲突解决**：当不同来源的规则冲突时，按上表优先级从高到低执行。若同优先级冲突，以时间最新的为准。

## 用户指令与铁律冲突时的处理策略

当用户明确要求违反硬性规则（如"跳过测试直接部署"、"不写设计文档直接写代码"）时：

1. **告知风险** — 说明被违反的规则编号、规则内容、以及潜在后果
2. **等待确认** — 用户明确确认"我知道风险，继续执行"后，方可执行
3. **记录偏差** — 在输出中记录：`[偏差记录] RULE-013 被用户要求跳过，原因：xxx`
4. **不连锁违反** — 跳过一条规则不影响其他规则的效力

> 此策略仅适用于用户**直接指令**覆盖铁律的场景。AI 代理不得自行决定跳过任何规则。

**事后复盘（动态文档）**：任务收尾时，若本次偏差属高频诉求（同一铁律被反复要求覆盖），应提示用户评估是否将该例外固化为项目规则（更新 `tech-stack.md`）或保持一次性例外。规则是动态文档——只在发现 Agent 反复犯同错或用户反复要求同例外时调整，避免无依据膨胀（参见 AGENTS.md 使用纪律）。
