# RULE-054 项目图形资产（1 张驾驶舱 + 9 张核心图）

> **唯一原则**：**一张图对应一个明确的决策动作**。没有决策动作的图不要上；有决策动作的图不许断更，也不许另起一份新图。
>
> **本条要解决的既有缺陷**：项目里的图长期是「每阶段各画一张 + 每次汇报重画一张」，于是同一个事实存在 5 份互不相同的读数（甘特 v1/v2/final/0930/1015），没人知道哪份作数，也没人维护它们。本条把图做成**有固定槽位、固定文件名、只就地更新的资产**，并用门禁抓重复图。

## 1. 十个固定槽位（不许增删，只许改状态）

| 槽位 | 文件（`docs/dashboards/`） | 覆盖阶段 | 回答什么问题 | **拍板动作（这张图的存在理由）** | 更新节奏 |
|---|---|---|---|---|---|
| **00** | `00-cockpit.md` | 全生命周期 | 项目健康度、里程碑、预算、风险、资源、发布是否正常 | 继续 / 加人 / 收缩范围 / 暂停 | 周 + 月 |
| **01** | `01-scope-wbs.md` | 立项、规划 | 做什么、不做什么、交付物边界、需求是否被覆盖 | 接受或拒绝范围变更 | 立项 + 变更 |
| **02** | `02-milestone-critical-path.md` | 规划、执行 | 何时做、依赖是什么、延期影响哪条链路 | 延期时砍范围还是加资源 | 周 |
| **03** | `03-flow-board-cfd.md` | 执行 | 任务流动是否顺畅、哪里堆积、谁被阻塞 | 调 WIP 上限 / 拆阻塞项 | 日 + 周 |
| **04** | `04-resource-load-heat.md` | 执行、监控 | 谁过载、谁闲置、关键技能是否瓶颈 | 调配人力 / 外购能力 / 收敛并行 | 周 |
| **05** | `05-evm-s-curve.md` | 监控 | 进度超前还是落后、成本超支还是节约（SPI/CPI） | 追加预算还是降档交付 | 周 + 月 |
| **06** | `06-risk-issue-matrix.md` | 全生命周期 | 哪些风险概率×影响最高、谁负责、何时关闭 | 关闭 / 升级 / 显式接受 | 周 |
| **07** | `07-architecture-dependency.md` | 设计、开发、运维 | 系统边界、服务耦合、循环依赖、变更影响面 | 拆分 / 合并 / 加隔离 / 排技术债 | 季度 + 变更 |
| **08** | `08-code-health.md` | 开发、交付 | 提交热力、PR 流转、覆盖率、长期分支是否健康 | 评审加人 / 技术债排期 / 分支收口 | 周 |
| **09** | `09-env-release-dora-slo.md` | 交付、运维 | 版本是否漂移、发布是否可控、线上是否健康 | 放行 / 回滚 / 冻结发布窗口 | 发布时 + 周 |

**复盘阶段不单开图**：在 `00-cockpit.md` 的「改进项跟踪」段把 事故 → 根因 → 改进措施 → 责任人 → 截止 串成时间线，闭环证据回指 `06` 的风险/问题 ID。

## 2. 只更新、不重生成（本条的牙齿）

1. **文件名 = 槽位号 + 固定 slug，永不含日期、版本号、`final`、`副本`。** 一次汇报要新读数就改这张表的数，历史留给 git。
2. 一个槽位在仓内**只允许一个源文件**；如需可视化产物，只允许同名的**唯一一份** `<槽位号>-<slug>.render.html`（由源文件生成，不得反向成为真源）。
3. 禁止把旧图另存为档案：`archive/` 里不再出现同一槽位的历史图——git 历史就是档案。
4. 重画（换口径、换图表形态）也算更新：在源文件里替换渲染，不新建文件；口径变化必须在「变化」段写明旧口径与新口径，并回指 `thresholds.md`。
5. 铺骨架只发生在项目开工时一次：`node <共享根>/hooks/scripts/dashboard-registry-check.mjs --root <仓根> --init`。该命令**发现任何槽位文件已存在即整体拒绝**，不会覆盖已有图。

> 判定：同一槽位出现第二份文件 = FAIL。这是本条唯一不可豁免的硬项。

## 3. 每张图的固定五段骨架

```markdown
## 决策        ← 这张图回答什么决策、谁拍、拍完落到哪个任务/分支（不许空）
## 读数        ← 表格，列内必须带统一 ID 与「绿/黄/红」列
## 图          ← mermaid / ASCII / render.html 引用，只此一处
## 变化        ← 本次相对上次的 delta（≤5 条），含口径变更；不写流水账
## 取数        ← 取数命令或端点 + 负责人 + `- last_updated: YYYY-MM-DD`
```

**自动取数优先**：能从 git / CI / issue / 监控脚本派生的数一律写取数命令，不手抄；必须人填的数在该行标 `人工` 并写日期。手写又没日期的数，视为不可信读数的来源缺失。

### 3.1 取数器与 `sources.json`（读数段的唯一写方）

- **规范实现**：共享根 `hooks/scripts/gen-project-dashboards.mjs`；各仓只放启动器 `tools/gen-dashboards.mjs` 转发（与门禁同形态，不留第二份取数逻辑）。
- **取数声明**：每仓 `docs/dashboards/sources.json` 只登记「从哪取 + 谁负责 + 缺哪些输入」，**不登记读数**。字段缺 → 对应指标在表里写「取不到」并点名缺哪一行输入；不许估算、不许用符号占位。
- **写入边界**：取数器只替换每张图「## 读数」段内 `<!-- AUTO:BEGIN … --> / <!-- AUTO:END -->` 之间的内容，并把 frontmatter 的 `last_updated` 盖章为当天；**决策 / 图 / 变化 三段属人工判断，工具永不覆盖**——这就是 §2「只更新不重生成」在工具层的落点。槽位为 `not_applicable` 时整槽跳过（不留假图）。
- **灯的唯一来源**：档位一律查本仓 `thresholds.md` 的绿/黄/红列，判次序 **红 → 绿 → 黄**；阈值表没有该指标行就不点灯，并把这条记进 00 的缺口清单。
- **灯格与指标名各占一格**：把指标名塞进灯格（`红（风险敞口 20）`）会让门禁的灯正则认不出这是灯，等于自造假绿。正确形态是灯格只留 `红/黄/绿/不点灯`，同行另有指标名列（06 的「档位依据」列、00 的「依据图 / 指标」列、08 的 ID 列）。
- **主源与交叉核对**：同一事实有多个台账时（如 A 仓的机器级发布审计 vs 仓内 `build-log.json`），sources.json 用 `deployAudit` 声明主源（支持 `%LOCALAPPDATA%` 展开），两源条数差本身写成一行读数，不做静默择一。

## 4. 统一口径与统一 ID

- **阈值表唯一真源**：`docs/dashboards/thresholds.md`，列固定为 `指标 | 口径 | 数据源 | 绿 | 黄 | 红 | 责任人`。任何图里的 🟢🟡🔴 必须出现在引用了该表某一行「指标名」的句子里——**灯不许靠感觉点亮，没有指标名的颜色即 FAIL**。
- **ID 贯穿链**：`M##` 里程碑 → `T##` 任务 → `R##` 风险/问题 → `I##` 改进项 → `C##` 架构组件 → `E##` 环境 → `V<sha>` 版本。跨图引用只准用这些前缀；门禁抽查 `00` 引用的 `M##` 是否能在 `02` 解引用，接不上即 WARN。
- 完成标准（DoD）、覆盖率分母、SLO 定义全项目一致，写进 `thresholds.md`，不在各图各自解释一遍。

## 5. 分期档位与最小可用组合

**按项目形态选档，不是越全越好**：

| 档位 | 适用形态 | 必跑槽位 |
|---|---|---|
| **MVP（3 张）** | 个人项目、单人单仓、无多人协同 | `00` 驾驶舱、`06` 风险矩阵、`09` 环境矩阵+发布看板 |
| **标准（7 张）** | 团队项目、多分支并行、有固定交付节奏 | MVP + `02` 里程碑/关键路径、`03` 看板+累积流、`05` EVM、`07` 架构拓扑+依赖 |
| **全量（10 张）** | 多项目治理、跨仓依赖、需资源负载与代码健康决策 | 全部；软件研发项目把 `08` 代码健康图列为优先补齐项 |

- MVP 档位下未跑的槽位仍按下方「槽位文件恒在」置 `status: deferred`，**不得删除文件**；降档无需 ADR，升档（MVP → 标准 → 全量）在 `00` 的「变化」段记录即可。
- 个人项目默认 MVP 档；被治理对象是个人项目时，门禁按 3 张口径判 `stale-beyond-cadence` 与 `09` 必填项，不按 10 张全量口径假红。
- **槽位文件恒在**：未做的槽位不删文件，而是在其 frontmatter 置 `status: deferred` + `reason` + `revisit`（复评日期）；「读数」段只写一行占位说明，**不许填数**（门禁判 `inactive-slot-with-readings`），防止半成品冒充已完成。
- 冻结 / 档案仓：置 `status: not_applicable` + `reason` 引用其 `AGENTS.md` 冻结声明；此时该槽位不得出现读数与灯。
- `registry.json` 由 `--emit-registry` 从各文件 frontmatter 派生，状态不手写（RULE-053 §3 同纪律）。

## 6. 生命周期阶段映射（谁在什么时候看哪张）

| 阶段 | 必看图 |
|---|---|
| 立项 / 规划 | `00` `01` `02` `06` |
| 设计 / 开发 | `07` `08` |
| 执行 / 监控 | `03` `04` `05` `06` `08` |
| 交付 / 运维 | `09` `07`（变更影响面） |
| 复盘 / 改进 | `00` 的改进项跟踪段 + `06` 闭环 |

分层展示：管理层只看 `00`；PM 看 `02` `05` `06`；执行层看 `03` `07` `08` `09`。同一数字只在一处维护，其余图引用它。

## 7. 常见坑 → 门禁可判形式

| 坑 | 门禁判定 |
|---|---|
| 同槽位多份图（`-v2/-final/日期/副本`） | `duplicate-slot` / `duplicate-artifact` = FAIL |
| 图里出现但清单没有（或清单有而磁盘没了） | `undeclared-artifact` / `stale-registry-entry` = FAIL |
| 只有图没有决策 | `empty-decision` = FAIL |
| 红黄绿靠感觉 | `light-without-metric`（未命中 `thresholds.md` 指标名）= FAIL |
| 图过期没人更 | `stale-beyond-cadence`：超 2× 节奏 = WARN，`00`/`09` 直接 FAIL |
| 风险图没有责任人与截止 | `06` 缺 `责任人`/`截止` 列 = FAIL |
| 发布图只看频率不看失败率 | `09` 必须含 DORA 四项 + 发布失败率 + SLO 达成，缺项 = FAIL |
| 代码图只看提交量 | `08` 必须含 PR 流转时长与评审等待，缺项 = FAIL |

## 8. 门禁与对账

- **canonical 实现**：`hooks/scripts/dashboard-registry-check.mjs`（共享根，零依赖）。各仓只放启动器 `tools/dashboard-check.mjs` 转发（与 RULE-053 的 `root-cleanliness-check` 同一形态，不留第二份判定表）。
- **清单必须派生**：`docs/dashboards/registry.json` 由门禁 `--emit-registry` 从各图 frontmatter 生成；提交前跑 `--check`，漂移即 FAIL（沿用 RULE-053 §3「清单必须派生 + 与磁盘对账」）。
- **自证**：`--selftest` 在沙箱内同时验正例（十槽齐备、颜色有指标名 → PASS）与反例（重复图、缺决策段、无指标名的灯、超期、僵尸清单条目一律被抓出）。门禁自身不通过 = 判定不可信，不得据其宣布合规。
- **收尾纪律**：交付说明里宣布「图已更新」必须附门禁输出与 `last_updated` 读数，不接受"我改了图"的自述。

## 9. 与既有规则的关系

- **RULE-053**：`docs/dashboards/` 是新增的 L3 产物落点（活文档，与带日期的 `docs/reports/` 分家）；目录本身仍按 L2「可核算」在 `tools/root-structure.json` 登记。
- **RULE-052**：图的派生产物（截图、render.html）不得落仓根。
- **RULE-051 / Cordis 形态**：`07` 架构拓扑的组件 ID 与 `plugins/registry.yaml`（派生清单）互相对账，图里的组件必须能在注册表解引用，注册表新增插件而图未更即 WARN。
- **`rules/project-status.md`**：`PROGRESS.md` 记事实流水与阶段状态；`00-cockpit.md` 只记读数与决策，不复制正文，只回指。
- **`rules/deploy-records.md` / `monitoring-rules.md` / `cicd-rules.md`**：`09` 的数据源。**`rules/tech-debt.md`**：`08` 的技术债台账回指。**`rules/priority-system.md`**：`01` 的范围判定依据。

## 10. 先例

- 2026-11-01：本条立规。触发点是同日目录结构收编批（RULE-053）之后复查发现：报告已有唯一真源与落点表，但"图"没有任何条款——同一事实在 A 仓存在多份甘特/里程碑快照，且没有任何一处声明哪份作数。
