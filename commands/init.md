# /init - 项目启动

**触发词**: "新项目"、"启动项目"、"立项"、"项目初始化"

---

## 命令语法

```
/init [project-name] [--type=fullstack|frontend|backend|data]
```

## 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `project-name` | string | 否 | 当前目录名 | 项目名称，用于生成项目目录和文档 |
| `--type` | enum | 否 | `fullstack` | 项目类型：`fullstack`（全栈）、`frontend`（纯前端）、`backend`（纯后端）、`data`（数据分析） |

## 触发场景

- 从零开始创建新项目时
- 需要明确项目目标、范围和技术选型时
- 需要进行可行性评估（技术/经济/时间）时
- 个人项目需要轻量化立项，确认技术栈和范围边界时

## 前置条件

1. 有初步的项目构想或需求描述
2. 了解目标用户和核心使用场景
3. 当前工作目录为空或可创建新目录

## 执行流程

1. **需求收集** — 识别利益相关方，收集核心诉求，定义问题陈述
2. **可行性分析** — 技术可行性评估、资源估算、风险识别
3. **范围定义** — 明确项目边界（MVP 范围 + 明确不做）
4. **技术选型** — 生成 `tech-stack.md`（基于项目类型模板）
5. **文档输出** — 生成 `docs/project-initiation.md` 立项文档

## 产出物

- `docs/project-initiation.md`：项目立项文档，含目标、范围、可行性、风险
- `tech-stack.md`：项目技术栈定义（基于模板自动生成）
- 项目目录结构（按 AGENTS.md §4 模板创建）

## 错误处理

| 常见错误 | 处理方式 |
|----------|----------|
| 项目需求过于模糊 | 引导用户通过结构化问题逐步明确 |
| 技术选型不确定 | 提供对比分析，列出推荐方案与备选方案 |
| 当前目录非空 | 询问是否在当前目录初始化或创建新目录 |
