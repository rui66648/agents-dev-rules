# /close - 项目收尾

**触发词**: "项目收尾"、"项目验收"、"复盘总结"、"归档"

---

## 命令语法

```
/close [--skip=acceptance|retrospective|archive]
```

## 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--skip` | enum | 否 | 无 | 跳过的收尾步骤：`acceptance`（验收）、`retrospective`（复盘）、`archive`（归档） |

## 触发场景

- 项目开发完成，运维稳定后，进入收尾阶段
- 需要对照项目启动时的成功指标进行验收
- 需要总结经验教训，沉淀知识
- 需要归档项目文档和代码，释放团队资源

## 前置条件

1. 所有功能开发完成，部署上线并稳定运行
2. `ops-monitoring` 运维监控已建立
3. `finishing-branch` 分支收尾已完成
4. 所有测试通过，代码审查通过

## 执行流程

1. **验收对照** — 对照 `project-initiation` 中的成功指标逐项验收
2. **测试报告** — 对照 `test-strategy` 中的测试报告确认覆盖率达标
3. **复盘总结** — 回顾项目全流程，识别做得好的、需要改进的
4. **知识沉淀** — 将经验教训写入项目文档，更新通用规则
5. **文档归档** — 确保所有设计文档、技术文档完整归档
6. **团队释放** — 确认无遗留任务，释放资源

## 产出物

- `docs/project-acceptance.md`：项目验收报告（对照成功指标）
- `docs/project-retrospective.md`：项目复盘总结（经验教训）
- 归档后的完整项目文档

## 错误处理

| 常见错误 | 处理方式 |
|----------|----------|
| 验收指标未达标 | 标记为已知问题，记录到复盘文档 |
| 文档不完整 | 补充缺失文档后再归档 |
| 有遗留任务 | 标记为后续迭代或技术债务 |

## 示例

```
/close
```

**预期输出**：
- 验收报告：7/8 成功指标达标，1 项标记为后续迭代
- 复盘总结：3 个做得好的，2 个需要改进的，1 个教训
- 归档状态：全部文档已归档
