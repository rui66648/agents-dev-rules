# /refactor - 代码重构

**触发词**: "重构"、"优化结构"、"清理代码"、"技术债务"

---

## 命令语法

```
/refactor [target] [--scope=file|module|system]
```

## 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `target` | string | 否 | 当前上下文 | 重构目标，如 `user-service`、`auth-module` |
| `--scope` | enum | 否 | `file` | 重构范围：`file`（单文件）、`module`（多文件模块）、`system`（系统级重构） |

## 触发场景

- 代码重复（相似逻辑复制粘贴）需要提取公共函数/组件
- 文件超过 300 行需要按职责拆分
- 死代码清理（未使用的导入/变量/函数）
- 技术债务偿还（rules/tech-debt.md 重构迭代周期）
- 架构调整需要重构模块边界

## 前置条件

1. 现有代码有测试覆盖（或重构前先补测试）
2. 当前分支干净，无未提交变更
3. 重构范围明确，不涉及功能变更（重构 ≠ 加功能）

## 执行流程

1. **现状分析** — 识别代码异味（重复代码、死代码、大文件、圈复杂度）
2. **目标定义** — 明确重构后的结构目标和验收标准
3. **安全网搭建** — 确认现有测试通过，补充缺失测试
4. **逐步重构** — 按文件/目录逐个处理，每次变更后立即运行测试
5. **验证确认** — 全部测试通过，功能无回归

## 产出物

- 重构后的代码（功能不变，结构优化）
- 补充的测试用例（如有）
- 重构记录（简要说明变更内容）

## 错误处理

| 常见错误 | 处理方式 |
|----------|----------|
| 测试覆盖不足 | 先补测试再重构，确保安全网 |
| 重构导致回归 | 回退变更，分析原因，缩小重构范围 |
| 重构范围过大 | 拆分为多个小型重构，逐个执行 |

## 示例

```
/refactor user-service --scope=module
```

**预期输出**：
- 重复代码：提取为 `shared/utils.py` + `shared/components/`
- 大文件拆分：`user_service.py`（450行）→ `router.py` + `service.py` + `repository.py`
- 测试：全部通过，无回归
