# /ops - 运维监控

**触发词**: "运维监控"、"日志查看"、"告警设置"、"健康检查"

---

## 命令语法

```
/ops [action] [--env=dev|staging|production]
```

## 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `action` | string | 否 | `status` | 运维操作：`status`（查看状态）、`logs`（查看日志）、`health`（健康检查）、`backup`（数据备份）、`monitor`（监控配置） |
| `--env` | enum | 否 | `production` | 目标环境：`dev`（开发）、`staging`（预发布）、`production`（生产） |

## 触发场景

- 项目上线后需要建立运维监控体系
- 需要查看服务运行状态和日志
- 需要配置告警规则和通知渠道
- 需要执行数据备份或恢复
- 定期巡检，确保系统稳定运行

## 前置条件

1. 项目已部署到目标环境
2. 有目标环境的访问权限
3. 监控工具已配置（如 Prometheus、Grafana、Sentry）

## 执行流程

1. **状态检查** — 检查服务运行状态、资源使用率、端口占用
2. **日志分析** — 查看最近日志，识别异常和错误
3. **健康检查** — 执行健康检查端点，验证服务可用性
4. **告警配置** — 设置告警规则（CPU/内存/错误率/响应时间）
5. **数据备份** — 执行数据库备份（如 `--action=backup`）
6. **文档输出** — 生成/更新 `docs/ops-manual.md`

## 产出物

- `docs/ops-manual.md`：运维手册（监控配置、告警规则、备份策略、应急响应）
- 运维状态报告（直接输出到对话）
- 备份文件（如执行备份操作）

## 错误处理

| 常见错误 | 处理方式 |
|----------|----------|
| 服务不可达 | 检查网络配置、防火墙规则、服务是否启动 |
| 日志级别不足 | 调整日志级别为 DEBUG 或 INFO |
| 备份空间不足 | 清理旧备份或扩展存储 |
| 告警风暴 | 调整告警阈值，合并重复告警 |

## 示例

```
/ops status --env=production
```

**预期输出**：
- 服务状态：API 正常运行 @ :8000，前端正常运行 @ :80
- 资源使用：CPU 45%，内存 2.3GB/4GB，磁盘 60%
- 最近错误：无（最近 1 小时）
- 健康检查：通过
