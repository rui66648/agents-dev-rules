# 市场与竞品研究参考（brainstorming 步骤 0 / 3 / 5 配套）

> 本文档按需加载。适用于：新产品立项、市场进入、竞品对比、用户画像分析，或用户提到时效性关键词（"最新"、"2026"等）。

## 1. 是否需要研究（判断表）

| 条件 | 执行研究 | 示例 |
|------|---------|------|
| 新产品/新平台设计 | ✅ | "我想做一个 AI 编程工具" |
| 竞品对比分析 | ✅ | "Cursor 和 TRAE 有什么不同" |
| 用户画像/市场分析 | ✅ | "目标用户是谁" |
| 市场趋势/最新数据 | ✅ | "2026 年 AI 编程工具趋势" |
| 现有功能迭代 | ❌ | "给我现有的登录页加个记住密码" |
| Bug 修复 | ❌ | "修复这个打印乱码的问题" |

## 2. 联网检索（高自由度启发式）

> 研究是开放性任务：**不限定搜索次数、不固定查询模板**。以下为覆盖维度和判断标准，按需取舍：

覆盖维度（尽力覆盖，允许合并）：

1. **市场规模与趋势** — 关键词方向：`[产品类别] market size <当前年份> growth`
2. **竞品功能与定价** — 关键词方向：`[竞品名] features pricing <当前年份>`
3. **用户痛点与社区反馈** — 关键词方向：`[产品类别] user pain points complaints`
4. **行业动态** — 关键词方向：`[产品类别] latest trends <当前年份>`

判断标准（何时停止）：

- 主要竞品（Top 5）的功能/定价信息已收集
- 市场规模数据至少有 2 个可交叉验证的来源
- 用户痛点有社区/论坛一手反馈佐证
- 新增搜索边际收益明显下降（重复结果）时停止

检索质量规则：

- 优先引用官方文档、权威报告、一手数据
- 所有数据标注来源 URL 和年份
- 关键数据交叉验证（至少 2 个来源）
- 单次检索超时 30 秒自动中止，降级到离线模式并在文档中标注"未验证"

## 4. 市场/竞品提问（initiative scope 或用户明确需求时）

配合 SKILL.md 的提问原则：独立问题可合并提出，存在依赖时再逐个追问；目标是尽快收敛，而非固定节奏。

**问题 5：** "目标市场是什么？（a) 现有市场切入  b) 新市场创造  c) 细分垂直市场"
**问题 6：** "你是否已了解主要竞品？有想对标或避开的功能吗？"
**问题 7：** "核心用户是个人开发者/团队/企业？他们每天使用时长期望是多少？"
**问题 8：** "如果涉及商业化，你倾向哪种模式？（a) 免费+订阅  b) 开源+企业版  c) 一次性买断  d) 内嵌服务收费"
**问题 9：** "与竞品相比，你认为最重要的差异化点是什么？"
**问题 10：** "为什么是现在做？市场时机是否成熟？"

## 5. 分析 Prompt 模板

### 市场/竞品分析模板

```
我想做一个 [产品名]，面向 [目标市场]，核心解决 [问题]。

请帮我：
1. 调研当前市场规模和增长趋势（最新数据）
2. 分析主要竞品（至少 5 个）的功能、定价、用户量、优劣势
3. 识别 2-3 个核心用户画像和他们的 Jobs-to-be-Done
4. 找出市场空白/差异化机会
5. 给出商业可行性评估（市场是否足够大、竞争是否过度）

输出格式：结构化 Markdown，包含数据表格和引用来源。
```

### 竞品对比模板

```
针对 [产品类别]，分析以下竞品的竞争格局：

## 关键洞察

## 差异化机会
- [机会 1]
- [机会 2]
```

### 用户画像模板

```
基于 [产品描述]，请创建核心用户画像：

1. 每个画像包含：
   - 姓名/角色/年龄段
   - 技术背景和日常工具
   - 核心痛点 (Frustrations)
   - 期望结果 (Gains)
   - 使用场景 (Use Cases)
   - 付费意愿 (Willingness to Pay)

2. 按"核心用户"→"次要用户"排序
3. 标注每个画像的优先级和占比估算
```

## 7. 数据幻觉反模式（研究专有）

- 编造市场规模数据 — 无来源支撑的百分比/金额
- 过时竞品信息 — 引用两年前的定价/功能
- 虚构用户画像 — 无社区/论坛反馈依据
- 夸大趋势 — 将个别案例泛化为行业趋势
- **缓解方法**：所有数据必须标注来源 URL，无法验证的数据明确标注"估计值"
