# HTML Document Center


## 负责代理

`docs-author` — HTML 文档中心生成由文档工程师代理负责，确保文档结构清晰、可维护。

## 何时使用

- 需要将项目文档（PRD、设计报告、技术白皮书、API 文档）生成为可交互的 HTML
- 需要创建一个统一的文档中心入口，支持分类浏览、搜索、内嵌预览
- 用户说"生成文档中心"、"做成 HTML"、"生成报告"、"文档可视化"
- 需要对比/展示多个文档，支持点击跳转查看

**触发关键词**: "HTML 文档"、"文档中心"、"生成报告"、"做成网页"、"可视化文档"

## 执行流程

### Phase 1: 需求确认与内容规划

> **交叉点提醒**：检查 `rules/workflow-html.md` 定义的横向交叉关系：
> - **交叉点 A**：是否有已审批的设计文档可转为 HTML 展示？（主流程 brainstorming → 文档流）
> - **交叉点 B**：是否需要基于已实现代码生成 API 文档？（主流程 executing-plans → 文档流）

0. **生成前查重（强制，RULE-053 §3.5；未完成不得进入第 1 步）**
   - 检索范围至少包含：目标仓 `docs/` 与 `docs/html/`、工作区 `outputs/`、根 `README.md` 入口表、已有文档中心 HTML。
   - 检索两类对象：① 同主题**正文真源**（md / 报告 / 盘点 / 方案）；② 已有**HTML 模板**（CSS 变量、topbar、三栏、TOC、深浅色交互）。
   - 命中处理：正文真源 → 就地修改；已有模板 → 在该文件上改，不另建视觉体系；仅当检索为空或已有件已冻结 / 归档 / 标注历史依据时才允许新建。
   - 把「检索路径 + 命中文件 + 判定理由」写进 `docs-author` 输入契约的查重结论。交叉点 A / B 命中时**必须**走「就地修改 / 指针化」，不能另起一份。
   - 派生纪律：Markdown 为内容唯一真源，HTML 只做导航与索引，通过 `fetch` / 链接加载正文，禁止把正文复制进 HTML。

1. **确认文档类型和数量**
   - 询问用户需要生成哪些类型的文档（PRD / 技术报告 / API 文档 / 设计规范 / 白皮书）
   - 确认每个文档的内容来源（已有 Markdown / 从零编写 / 基于代码生成）

2. **确认视觉风格**
   - 暗色主题（推荐，适合技术文档）
   - 亮色主题（适合商务/产品文档）
   - 渐变毛玻璃（Fresh Gradient，适合现代产品）

3. **确认文档中心架构**
   - 单页应用（SPA）：左侧导航 + 右侧 iframe 预览（推荐）
   - 静态页面集合：独立 HTML 文件 + 索引页
   - 混合模式：索引页 + 独立文档页

### Phase 2: 生成文档内容（逐文档）

每个文档遵循以下流程：

```
内容规划 -> HTML 生成 -> 样式美化 -> 验证 -> 集成到文档中心
```

**内容来源处理：**

| 来源 | 处理方式 |
|------|----------|
| 已有 Markdown | 使用 marked.js 转换 + 自定义 CSS |
| 从零编写 | 直接编写 HTML，遵循 html-report 技能规范 |
| 基于代码/数据 | 使用 ECharts/Mermaid 生成图表嵌入 |
| 多源聚合 | 先统一为 Markdown，再转换 |

**HTML 生成规范（遵循 html-report 技能）：**

1. **目录结构**（每个文档独立目录）：
   ```
   docs/
   ├── doc-center.html              # 文档中心入口
   ├── prd/
   │   ├── index.html               # PRD 文档
   │   └── assets/
   ├── tech-report/
   │   ├── index.html               # 技术报告
   │   └── assets/
   └── api-doc/
       ├── index.html               # API 文档
       └── assets/
   ```

2. **CSS 变量系统**（统一主题）：
   ```css
   :root {
     --bg: #0B0D12;           /* 页面背景 */
     --bg2: #111827;          /* 卡片/面板背景 */
     --ink: #E4E6F0;          /* 主文本 */
     --muted: #989CB4;        /* 次要文本 */
     --rule: #2E3348;         /* 边框/分割线 */
     --accent: #34D399;       /* 主强调色 */
     --accent2: #60A5FA;      /* 次强调色 */
     --accent3: #FBBF24;      /* 第三强调色 */
   }
   ```

3. **组件规范**：
   - 图表：使用 ECharts（必须内联或本地引用）
   - 流程图：使用 Mermaid（必须内联或本地引用）
   - 代码块：使用 Prism.js 或自定义高亮
   - 表格：响应式，支持横向滚动

### Phase 3: 生成文档中心入口

**文档中心入口页（doc-center.html）结构：**

```
┌─────────────────────────────────────────────────────┐
│  [Logo]  Project Docs          [Search...]   [Theme] │  ← Header
├──────────┬──────────────────────────────────────────┤
│          │                                          │
│  📁 分类A  │                                          │
│    ├─ 文档1  │        [iframe src="doc1.html"]       │  ← Content
│    ├─ 文档2  │                                          │
│  📁 分类B  │                                          │
│    ├─ 文档3  │                                          │
│          │                                          │
│  [Stats] │                                          │
│          │                                          │
├──────────┴──────────────────────────────────────────┤
│  Generated by Trae Work                              │  ← Footer
└─────────────────────────────────────────────────────┘
```

**核心功能：**
1. **左侧导航树**：分类折叠/展开，文档列表，点击在右侧 iframe 加载
2. **全局搜索**：实时过滤文档标题和描述
3. **面包屑导航**：显示当前查看的文档路径
4. **统计面板**：文档数量、分类分布、最近更新
5. **响应式**：移动端自动折叠侧边栏

**iframe 加载策略：**
```javascript
// 点击文档时，在 iframe 中加载对应 HTML
function loadDocument(url, title) {
  document.getElementById('doc-frame').src = url;
  document.getElementById('doc-title').textContent = title;
  updateBreadcrumb(category, title);
}
```

### Phase 4: 集成与验证

> **交叉点 D 提醒**：HTML 文档中的 API 示例代码必须与实际接口一致。验证时需反向检查：对比文档中的 API 路径、请求/响应 Schema 与实际代码实现。若发现不一致，暂停并报告（文档流 → 主流程）。

1. **验证所有链接可点击跳转**
2. **验证 iframe 内文档样式独立**
3. **验证搜索功能正常**
4. **验证响应式布局**
5. **验证暗色/亮色切换（如支持）**
6. **交叉验证**：API 文档中的示例与实际接口一致性（交叉点 D）

## 与现有工作流的集成

```
brainstorming -> writing-plans -> html-document-center -> verification
                    ↓
            [生成文档中心计划]
                    ↓
            [生成各文档 HTML]
                    ↓
            [生成中心入口页]
                    ↓
            [集成验证]
```

**与 Superpowers 流程的对应：**
- `brainstorming` -> 确认文档类型、风格、架构
- `writing-plans` -> 规划每个文档的章节和内容
- `html-document-center` -> 执行 HTML 生成（本技能）
- `verification` -> 验证所有链接、样式、功能

## 硬性规则

- ✅ 每个文档必须有独立的 `assets/` 目录存放图片/图表
- ✅ 所有文档必须使用统一的 CSS 变量主题，确保视觉一致
- ✅ 图表必须使用 ECharts 或 Mermaid，禁止外部图片替代数据可视化
- ✅ 文档中心入口页必须使用 iframe 隔离各文档样式，避免冲突
- ✅ 所有文档链接必须可点击，禁止使用不可点击的占位符
- ❌ 禁止使用 CDN 外链（除 ECharts/Mermaid 等必要库外），优先本地文件
- ❌ 禁止在一个 HTML 中嵌入过多文档内容（>500KB），应拆分为独立文件
- ❌ 禁止忽略移动端适配
- ❌ 禁止跳过验证直接声称完成

## 反模式

- ❌ 将所有文档内容塞入一个巨大的 HTML 文件 -- 加载慢、难以维护
- ❌ 文档间样式互相干扰 -- 必须使用 iframe 隔离
- ❌ 使用截图替代可交互图表 -- 失去数据可视化的价值
- ❌ 文档中心没有搜索功能 -- 文档多后无法快速定位
- ❌ 忽略暗色主题 -- 技术文档默认暗色更符合开发者习惯
